# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

muxterm is an iTerm-style terminal emulator for macOS (Rust, egui/eframe) where **every pane is backed by its own tmux session** on a dedicated socket (`tmux -L muxterm`). Quitting the app only detaches clients — sessions, processes, and scrollback survive; relaunch reattaches the saved layout. Requires `tmux` on the machine (`make setup` installs it via brew).

## Commands

```sh
cargo run --release          # run the app (also: make run)
cargo build                  # compile check
cargo test                   # all tests (root crate; unit tests live in #[cfg(test)] modules)
cargo test layout            # tests in one module
cargo test split_and_leaves  # single test by name
cargo run --bin mux -- peers # the mux CLI (second binary; default-run is the GUI)
make install                 # bundle muxterm.app (make app) + ship to /Applications + refresh ~/.cargo/bin/mux
```

The bundle recipe lives in the Makefile and `packaging/` (Info.plist template, icon generator); `assets/muxterm.icns` is checked in — regenerate with `make icon` only when the icon design changes.

`make cert` (once per machine, `packaging/make-signing-cert.sh`) creates a persistent self-signed `muxterm-local` code-signing identity in the login keychain **and trusts it for code signing** (`security add-trusted-cert`); `make app` signs with it when present (`SIGN_ID`), else ad-hoc. This is what stops macOS re-prompting for TCC "access data from other apps" on every rebuild (the agent-hook installer touches `~/.claude`/`~/.codex`/`~/.pi`/`~/.config/opencode` — other apps' dirs — and TCC pins the grant to the *designated requirement*, which for an ad-hoc signature is the ever-changing binary hash but for the cert is the stable bundle-id + cert leaf). The **trust** half is not optional: an untrusted self-signed cert is rejected by `spctl` and TCC won't anchor the grant on it, so it degrades back to the per-build hash and re-prompts — the exact failure the persistent cert is meant to prevent. The script is self-repairing: run `make cert` again on a machine whose `muxterm-local` cert exists but isn't trusted and it just adds the trust setting (then `tccutil reset SystemPolicyAppData dev.herval.muxterm` and re-Allow once).

There is no test binary/harness beyond inline unit tests, and no rustfmt/clippy config — match the existing hand-formatted style (notably `},` closing match arms).

## Architecture

Cargo workspace: the root `muxterm` crate plus `crates/egui_term`, a **vendored** terminal widget (egui + alacritty_terminal) carrying local patches (input gating, SGR mouse-wheel under tmux mouse mode, bracketed paste, IME, OSC 52 copy). Any change under `crates/egui_term/` must be recorded as a patch entry in `crates/egui_term/VENDOR.md`.

Two binaries share one library. `src/lib.rs` exposes only `agent`, `ask`, `layout`, `mesh`, and `state` — the modules used by both the GUI (`src/main.rs` + private modules) and the agent-mesh CLI (`src/bin/mux.rs`). Code needed by `mux` must live in one of those modules.

### The tmux trick (persistence)

- `tmux.rs` — each pane's PTY runs a tmux *client*: `tmux -L muxterm new-session -A -D -s mux-<8hex>`. `-A` makes fresh-spawn and restore-after-relaunch the same code path. Killing a session is an explicit step (cmd+w / shell exit); dropping a `Pane` merely detaches. The tmux.conf is regenerated at every launch.
- `state.rs` — layout (windows → tabs → split tree → session names) is saved to `state.json` on every mutation. On startup, `mux-*` sessions not referenced by the state are GC'd — **never when the state file failed to parse** (a corrupt state must not cost live sessions).
- **Reboot recovery** (config `session_recovery`/`restore_scrollback`/`restore_agents`, all default on): the tmux trick only survives an app *quit* (detach) — a machine reboot kills the server, and with it every session's process, cwd, and scrollback, so `new-session -A` on next launch silently mints fresh empty shells. Layer 1 (`NodeState::Leaf.cwd`, serde-`default`, snapshotted from `pane_snap` on the poll tick — the tick marks state dirty when a cwd moves so it's never stale) feeds each restored pane's saved cwd back as the fresh session's `-c` start dir (honored on create, ignored on a warm reattach — so `App::new` computes the **cold** set once from `list_sessions()` and only recovers leaves the socket no longer holds). This *also* fixes a self-inflicted second loss: fresh panes coming back in `/` used to make `sync_workspace_roots` retarget every workspace off its worktree (`worktree = None`) — Layer 1 lands panes back inside the worktree so `retarget` bails, plus a `WORKSPACE_SYNC_GRACE` startup window guards the settling. Layer 2 (`scrollback.rs`, a poller mirroring `git_status.rs`) captures each live pane's tail to `~/.muxterm/scrollback/<session>.txt`; on a cold restore the dir is rotated to `scrollback-prev/` (so the restarting poller can't clobber it) and `restore_tab` replays it via a framed `cat` (plain text — nothing runs). Layer 3 relaunches a cold task-workspace's agent CLI interactively via `relaunch_agent_for_recovery` (`agent::resume_command` — bare CLI, **no** task prompt, since re-running mid-flight work could corrupt it). Running processes are unrecoverable by design. Test a reboot without rebooting: `tmux -L muxterm kill-server`, then relaunch.
- Everything lives under `~/.muxterm/`: `config.toml`, `state.json`, `tmux.conf`, mesh state (`agents.json`, `inbox/`, `ctx/`), scrollback captures (`scrollback/`), and workspace git worktrees (`worktrees/`). `state::config_dir()` is the single source of truth (mesh's delegates to it); `state::migrate_config_dir()` (called first thing in both binaries' `main`) moves the dir over from the old `~/Library/Application Support/muxterm/` once, idempotently. Because the socket is dedicated, you can inspect the app from outside: `tmux -L muxterm list-sessions`, `capture-pane`, etc.

### GUI (private modules)

- `app.rs` — the eframe App: owns `Vec<Tab>`, routes PTY events from a shared mpsc channel keyed by pane id, applies keyboard `Action`s (`keys.rs`), persists state, and polls `config.toml` mtime for live reload (`config.rs`).
- `layout.rs` — binary split tree per tab (`Node`, leaves are `PaneId`s), rect splitting, and directional focus (`neighbor`) computed from last-frame screen rects.
- `theme.rs` / `tabbar.rs` — chrome colors are *derived* from the terminal palette; themes are curated presets that carry a whole look — palette, font (`FontSpec`: Monaco for the iterms, bundled Px437 VGA for bbs, SF Mono for github-light), focused-border width, and a pane HUD bar (`BarSpec`: floating `chips` like the iterms, or a full-width `solid` strip that *reserves layout space* — bbs wears an inverse-video green top bar, github-light a blue bottom bar; optional explicit bg/fg/accent, else derived so chips stay pixel-identical; `theme::hud_colors` guards low-contrast status icons on solid strips) — the HUD text (title badge, chips, search-bar hints) renders in the theme's *own* face at `BarSpec.font_size` (iterms 11, bbs 16 for crisp native VGA, github 11), registered under its own egui family `theme::BAR_FONT_FAMILY` (`config::install_fonts`) so it stays pinned to the theme even when the terminal `[font]` is overridden, and surfaced as `UiTheme.bar_font` (a `FontId`, threaded free to every HUD draw fn) — with small `[colors]`/`[font]` override surfaces plus `bar_background`/`bar_foreground`/`bar_accent` color keys and flat `bar_style`/`bar_position`/`bar_font`/`bar_font_size` knobs (the last two override the HUD face + size independent of `[font]`). Solid-strip geometry has one owner, `app::split_bar` — the terminal grid, the HUD line, the search bar, and the "?" caret must all split through it.
- `links.rs` — cmd+click opener (egui_term P10 detects URL/path tokens and calls the pane's `set_link_opener`): URLs open directly; paths get `:line:col`/punctuation stripped, `~` expanded, relative resolved against the pane's live cwd (tmux `pane_current_path`), and open only if they exist — the existence check is what filters regex false positives like `and/or`. One function, `resolve_target`, is the whole judgement (PR number → URL → existing path), and it runs on **hover** too (egui_term P28 `set_link_validator`): the widget's wrap-rejoin (P20) produces *guesses*, so underlining the longest one made the highlight disagree with the click — now the underline covers exactly the candidate that will open, and a token that opens nothing never lights up. Hover answers from the App's once-a-second pane-cwd snapshot (`tmux::SharedPanes`), not a tmux call, and the widget memoizes it per grid cell. Agent CLIs box their output behind a gutter glyph (codex `| `, claude code `⎿ `, `└ `/`│ `), which used to truncate any path they hard-wrapped across rows and make the continuation unclickable; P27 treats a leading pure-gutter run as chrome and drops it from the join.
- `search.rs` — the cmd+f scrollback search (`SearchBar`): the local grid holds no history (egui_term P9 caps it; tmux owns scrollback), so the bar only owns the keyboard and the query — every edit drives tmux copy-mode server-side in one invocation (`copy-mode ; history-bottom ; search-backward-text -- <q> ; display-message` for the counter), and highlights/scrolling come back through the PTY. Match styles in tmux.conf derive from the theme (`theme::search_highlight`). Esc closes the bar with zero tmux calls, leaving copy-mode at the match.
- `pr_status.rs` — GitHub PR chips (config `pr_status`, default on) on the pane's HUD bar: a poller thread maps pane cwds → (repo root, branch) locally every few seconds, asks `gh pr view` per unique key at most once a minute (merged/closed PRs on a 10-minute TTL), and streams `session -> Vec<Badge>` snapshots to the App over an mpsc channel; the JSON→Badge rollup is a pure fixture-tested function. The poller *remembers* every branch that had a PR per root (`~/.muxterm/pr_memory.json`, survives relaunch; refreshes go by PR number so branch deletion after merge doesn't lose the chip), so a pane shows chips for **all** PRs its checkout has touched, not just the current branch's — until the root disappears or the user right-clicks a merged/closed chip off (a `Dismissed` set shared App↔poller). Each chip is a painter-drawn state icon (shape *and* color, `Kind::draw_icon`: red ✗ CI failing/changes requested, yellow dot pending, green ✓ open/awaiting review, green sealed-✓ approved (review APPROVED, split from plain open so a signed-off PR reads distinctly), hollow ring draft, magenta merge-glyph merged, dim minus closed) plus `#number`; left-click opens the PR. Chips render next to the pane-title badge (`draw_pane_title`; lone panes get chips without a title).
- `pr_monitor.rs` — the sidebar's **open-PR section** (config `monitor_prs`, default off, toggled on Settings' *extras* tab). A sibling poller to `pr_status`, deliberately separate: `pr_status` answers "does *this checkout's* branch have a PR" and is keyed by (repo root, branch), while this answers "what am I working on everywhere", which needs a GitHub identity and one cross-repo `gh search prs --author=@me --state=open`. That search **cannot return a head branch** (the search API has no such field), so the branch is fetched lazily by `head_branch` (`gh pr view --json headRefName,isCrossRepository`) once, inside the checkout worker — the list stays one call and the per-PR cost lands only on the click that needs it. Same thread shape as `pr_status` (idles and sends one clearing snapshot when disabled, focus backoff, TTL + error backoff, send-on-change), but a failure is *surfaced*: the `Snapshot.note` is painted where rows would be, because a whole section rendering empty reads as broken where a missing chip does not. A row's **body reads** the PR in an overlay (`pr_view.rs`, `preview_pr`) - deliberately *not* a pane, because every pane is a tmux session that outlives the app and a glance should not leave one behind; `gh pr view` + `gh pr diff` are fetched off-thread and rendered over the terminal like Settings, coloured from the diff's line prefixes (gh writes plain text when it isn't a tty, so there is no ANSI to parse, and `---`/`+++` are matched before `-`/`+` so file headers don't read as removals and additions), with `show_rows` so a thousand-file diff costs what a one-line one does. Esc closes it; a `check out ↓` button turns the look into a workspace. The trade is that it is not a terminal: no cmd+f, no tmux scrollback, egui's selection rather than copy-mode's and its **↓ button checks it out**, the same body-vs-icon split the workspace rows use. Checkout is two-phase, because the decision needs the head branch and that costs a call: `spawn_pr_head` resolves it off-thread (cached per PR, which also lets a row know it is already open in a workspace made some other way), then `open_pr_workspace` picks between three outcomes - focus the workspace that already has that branch, open the worktree that already holds it (`worktree_for_branch`: `git worktree add` refuses a branch checked out elsewhere, which is the *normal* case for a PR muxterm itself raised), or check it out fresh via `spawn_pr_worktree`, which clones the repo if it isn't local, **fetches**, then puts the head branch in a `pr-<number>` worktree — the fetch is load-bearing, since a branch pushed since the last fetch resolves as `New` and would fork an empty branch off HEAD that looks like the PR. It reports over the same `WorktreeMsg` channel as cmd+n, so the progress chip, failure walk-back and agent launch all apply unchanged. The repo's local root is found via the Projects registry (normalized `repo_key`), then any open pane's checkout of it, then `~/.muxterm/clones/`. `Workspace.pr` remembers which PR a tab came from, so its row shows as already open. Fork PRs (`isCrossRepository`) are refused with a message — their branch is in another repo, out of `--track`'s reach.
- `git_status.rs` — git branch chips (config `git_status`, default on): a poller thread runs `git status --porcelain=v2 --branch` once per unique pane cwd every few seconds and streams `session -> Git` snapshots to the App over an mpsc channel — all local, no network, no TTL cache (mirrors `pr_status`'s local scan but skips the `gh` fetch). The porcelain→`Git` parse (branch, dirty count, ahead/behind) is a pure fixture-tested function. Chips render in `tabbar.rs` (display-only, left of the PR chip) and next to pane-title badges; dot is green when clean, yellow when dirty.
- `attention.rs` — activity/attention tab badges (`Cell`, an Instant-injected egui-free state machine like the "?" prompt's): `PtyEvent::Wakeup`/`Bell` — already delivered per-pane to `drain_pty_events`, no tmux hooks — mark background panes (dim dot for output, warn dot for bell or `mux notify`); a per-frame sweep clears the active tab's cells while the window is focused, so every tab-switch path acknowledges badges for free. Attention rises also bounce the dock and post an osascript banner (text via env vars — no AppleScript quoting surface) when the window is unfocused, gated by config `notifications` (default on). A `STARTUP_GRACE` per cell absorbs the tmux attach redraw on restore/split.
- `workspace.rs` / `workspace_popup.rs` / `sidebar.rs` — **every tab is a workspace** (`Tab.workspace: Workspace`): a bare shell for cmd+t, or a rich one for cmd+n (a project folder, an optional git worktree, the task prompt, agent+model, and a title that shows instantly as a prompt-derived placeholder (`workspace::placeholder_title`, the prompt's first words) then upgrades out of band to a short AI title: `workspace::spawn_title` one-shots the workspace's agent CLI on its fast model (`agent::oneshot_command`, e.g. `claude -p --model haiku`) off the UI thread, and the App's `naming` set discards a late result if the tab was killed or `mux rename`d first — best-effort, the placeholder stays on any failure. Prompt-less workspaces and bare cmd+t tabs keep a random adjective-animal codename (`random_title`, entropy via uuid v4); `mux rename` is how any workspace gets a deliberate name). The cmd+n popup gathers those; `App::create_workspace` makes the worktree under `~/.muxterm/worktrees/` (outside the repo so `git status` stays clean), opens a single agent pane in it (the tree's only — hence *first* — leaf: `launch_agent` types into `first_leaf()`; the user splits with cmd+d when they want a side shell, and `cd_side_panes` walks any panes split mid-checkout into the landed subdir / back out on failure), and types the agent's interactive launch command into the agent pane (`agent::launch_command`, same `BackendCommand::Write` path the "?" prompt uses). The popup's branch typeahead decides the worktree's branch (`workspace::BranchChoice`, resolved by pure `resolve_branch` against `list_branches` — one `for-each-ref` over refs/heads+refs/remotes, newest-first, `%(worktreepath)` marking checked-out branches the picker dims): empty field → new codename branch (`-b`, dir and branch share the codename — deliberately not prompt-derived, keeping the task's words out of branch names); an existing local branch → plain checkout; a remote-only branch → `--track -b`; an unknown name → `-b` with that name (dir = branch with `/`→`-`, dir alone suffixes on collision; a user branch name is never silently renamed — a race just fails into the walk-back-to-root recovery). `claim_worktree` picks the dir synchronously (mkdir is the claim); `populate_worktree` runs the variant's `git worktree add` off-thread, the worker narrating over the worktree channel (`WorktreeMsg::Progress`/`Done` — "cloning…", "fetching…", "checking out…") which the App floats as a chip over the agent pane (`draw_worktree_progress`) until Done lands. Metadata rides inline in `state.json`'s `TabState.workspace` (serde-`default`, no VERSION bump). The root **follows the panes**: once *no* pane in a tab is left under the root/worktree or anywhere in their git repo, a per-second sweep (`App::sync_workspace_roots`, riding the same `list-panes` snapshot as the status dots — `pane_snap`) repoints `workspace.root` at the focused pane's repo toplevel (or bare cwd) and drops the stale worktree link; one pane still inside pins the reference (decision logic: `workspace::retarget`, pure and unit-tested; tabs with a checkout in flight are skipped via `pending_worktrees`). The collapsible left sidebar (cmd+\, `SidePanel::left`) lists workspaces in tab order (matches cmd+1..9) — flat, no status groups in v1. Every section folds to its header (`section_header`, the fold persisted in `state.json`), the live list included: the panel's own "Workspaces" title *is* that section's header rather than a second one saying the same word, so its click band is held off the trailing ‹/+ buttons by `HEAD_BUTTONS_W` and folding it hides only rows — cmd+1..9 still reach the tabs. Each row's status dot is **hook-driven, AI agents only** (`agent_hooks.rs`): at launch muxterm idempotently merges lifecycle hooks into `~/.claude/settings.json` and `~/.codex/hooks.json` (UserPromptSubmit/PreToolUse → working, Stop → idle, Notification/PermissionRequest → attention — claude's Notification hook carries a `permission_prompt|elicitation_dialog` matcher so the ~60s idle_prompt nudge can't repaint an idle agent as attention, SessionEnd → gone) and drops a generated TS extension in `~/.pi/agent/extensions/` (agent_start/agent_end/session_shutdown); every hook shells `mux agent-event <state>`, which writes `~/.muxterm/agent-state/<session>.json` keyed by MUXTERM_SESSION (inert outside muxterm, drains stdin, always exits 0 — a PreToolUse hook must never block a tool). It stays silent on stdout except on the UserPromptSubmit hook, which carries `--nudge-name`: while the tab still wears its `random_title` codename, `name_nudge` prints a one-line "rename me now that a task started" reminder that claude injects as prompt context (self-suppressing once renamed; the flag rides UserPromptSubmit alone — never PreToolUse, whose stdout claude reads as a permission decision). The GUI reads the dir on its 1s poll tick and prunes entries whose pane's foreground returned to a shell (the same per-second `list-panes -a` snapshot, `pane_snap`), so a killed agent's light goes out without its end hook. The status icon is a shape per state, not just a color (readable without color vision; painter-drawn in `sidebar::status_icon`, no font-glyph width gambles): breathing green play-triangle = working, breathing *hollow* green play-triangle = an idle claude's `run_in_background` shell still running (no hook exists for those — an off-thread `ps` walk under `#{pane_pid}` on the 1s tick looks for the `shell-snapshots/snapshot-` argv marker, `bg_jobs.rs`, idle sessions only since a marker under a working agent is just a foreground Bash tool), steady red exclamation = attention (also bell/`mux notify`), hollow accent ring = idle; non-agent programs never light it.
- **Agent registry + hooks** (`agent.rs`, `agent_hooks.rs`): Claude, Codex, Pi, and OpenCode share one registry for probing, settings, workspace launches/recovery, `mux ask`, and title one-shots. OpenCode is provider-agnostic: an empty model entry means its configured default, while curated explicit entries are provider-qualified OpenCode Zen ids; its interactive task must use `--prompt` because the positional argument is a project path, while asks/titles use `opencode run`. Status is an auto-discovered global JS plugin at `~/.config/opencode/plugins/muxterm-status.js`; it aggregates busy child sessions and maps permission/question/error events to attention so a child going idle cannot extinguish a working parent.
- **Projects** (cmd+shift+n): a saved registry of workspace sources (`workspace::Project` ↔ `state::ProjectState`, riding in `state.json`'s top-level `projects`, serde-`default`) — a folder on disk or a GitHub repo (repo projects auto-clone on first use into `~/.muxterm/clones/`, never GC'd, via `spawn_clone_worktree`: clone → re-resolve the typed branch against the fresh clone → `populate_worktree`. `clone_url` is **verbatim** except bare `owner/repo` → github https — deliberately no protocol fallbacks: the popup's async `git ls-remote --heads` (`spawn_remote_branches`, polled + repo-cached by `poll_remote_branches`) doubles as a *preflight* — reachable feeds the same `branch_picker` typeahead, unreachable paints a warn row and **blocks Create** (`submit_blocker`, also guarding cmd+enter and re-checked in `create_workspace`), so a workspace whose clone would fail is never created), plus an optional repo-relative **subfolder** (monorepo apps: the worktree is still the whole repo — clones are keyed by *repo* (`clone_dirname`), so sibling subdir projects share one clone — and every pane cd's into `<worktree>/<subdir>` once the checkout lands, `workspace::boot_cd` + `cd_side_panes`; the derived project name becomes `repo/subdir`) and an optional multiline **setup script** that `launch_agent` types into the first pane line-by-line after that cd and before the agent's launch command (the `Workspace` copies `setup`/`subdir` at creation, so editing/removing a project never touches a live tab; a plain cmd+n worktree also inherits a saved project's setup when the picked folder unambiguously matches one — by path, or by origin URL for repo projects, `workspace::inherited_setup` — subdir is never inherited). cmd+shift+n opens the cmd+n popup in project mode (`NewWorkspaceForm::for_project`: project rows instead of the folder field, worktree always on) — or Settings on the Projects tab when the registry is empty. Project mode freshens only what the branch choice consumes before checkout (`refresh_base`, best-effort off-thread: `fetch origin b:b` for a chosen existing branch, the remote-tracking ref for a tracked one, the clone's own branch + ff for codename/new in a muxterm-owned clone — nothing at all for codename/new on a user repo, whose HEAD is never moved), every fetch under a ~20s kill-timeout (`agent::output_with_timeout`, shared with `mux retitle`) so a hung remote degrades to local state. A failed checkout/clone echoes one `[muxterm] worktree failed: ...` line into the pane, walks the panes back (root, or home when the root never came to be — a failed clone) skipping the setup script, and repoints `workspace.root`; the claimed dir is deliberately **not** deleted (yanking a booting shell's cwd showers it with getcwd errors) — `sweep_stale_claims` reclaims empty, unreferenced, pane-free claims at the next launch. Managed in Settings — five tabs (appearance / preferences / projects / templates / extras, `settings::Tab` on the App; `COLS` is sized to the selector row, so a sixth label means widening it): the Projects tab lists rows (click loads the add form's draft; `[ add ]` upserts by name — that round trip is the edit path; `[x]` removes) and persists via `save_state`, not config.toml (its line-surgery writers can't hold a list).

### The "?" AI prompt

**The prompt is a process, not a widget.** `ai_prompt.rs` (`LineTracker`, `on_event`) watches egui input events **before** `TerminalView` sees them for one thing only: a `?` typed as the first char at an idle shell prompt. That `?` never reaches the shell — `ai_intercept` swallows it and types `mux ask -i` into the pane instead, then steps out. Everything after the handoff (typing the question, editing it, submitting, leaving) belongs to that foreground process and the tty, so it behaves like any REPL you'd ssh into: `? ` prompt, answer, `? ` prompt, ctrl+c/ctrl+d back to the shell. `LineTracker` heuristically models the shell's input line and must err toward `Dirty` — a missed trigger is harmless, a false one intercepts real typing. The typed command **erases itself**: the GUI works out where the shell's echo of it will land (`App::inline_ask_command` + `echo_rows_up`, from `tmux::cursor_and_size` — cursor column, pane width/height) and passes it as `--inline <rows-up>,<col>`; `ask::erase_echo` moves back up over the echo, returns to the prompt's end column and clears from there down, so the first `? ` lands exactly where the user's `?` did and the pane reads as if they had asked at their own prompt. The flag's own characters are typed too, so the row count is a fixed point the builder iterates to; untrustworthy geometry just leaves the command visible. `ask::repl` (behind `mux ask -i`) is the loop: prompt, `read_line`, capture the pane's last N lines (`agent_context_lines`, read from config.toml by `mux ask` itself now — fresh **per question**, not once at entry) and hand them to the agent on **stdin through a pipe** (`feed_context`, written off-thread so a capture larger than the pipe buffer can't deadlock the stream reader). ctrl+d ends the loop; ctrl+c reaches the whole foreground group, so it takes any in-flight query with it — both read as "back to the shell". `ask.rs` also resolves agent + `agent_model` from config.toml, spawns the CLI — `claude -p` with stream-json, or an Exec-style agent (`codex exec`, `pi -p`) which streams natively — and renders answer text live with tool calls as dim `»` one-liners. Waiting is shown by a **spinner, not a `thinking` line** (`Pulse`): a ticker thread draws an ASCII frame once the pane has been quiet for 250ms and every write erases it first, so one rule — quiet means spin — covers the pause before the first token, the gaps around tool calls, and the turn after a y/N, while an answer that starts promptly never flashes one and nothing is left in the scrollback. It shares the renderer's terminal gate (so it can't interleave with output or the approval prompt), skips mid-line waits (its erase clears a whole line), and is `None` when stdout isn't a terminal. Thinking blocks render as nothing at all — extended thinking is on by default in claude's CLI with no off-switch (`--effort` doesn't disable it), and it isn't a state the reader can act on. Answers are shaped to read like command output rather than chat (`STYLE_HINT` in claude's appended system prompt, `STYLE_TAG` appended to the question for every agent — the trailing tag is the half that actually lands; the system prompt alone still yields markdown and a menu of alternatives). The agent **acts, not just answers**: claude runs with `--dangerously-skip-permissions` (headless `-p` has no prompt to approve through), codex with `--sandbox workspace-write`, pi's print mode acts unrestricted by default. Mutating tools are gated behind an interactive **y/N** — a claude PreToolUse hook (`mux approve`, wired via `--settings`) that, because claude runs hooks with no controlling terminal, *relays* each request over a unix socket to the `mux ask` parent, which owns the pane's `/dev/tty` and does the asking (fail-closed: no socket → deny). Read-only tools (Read/Grep/Glob) never reach the hook, and **a Bash call that only reads doesn't spend a prompt either**: `shell_is_read_only` allows it outright, because a y/N on every `ls` is worse than no gate — it trains you to approve without reading. That classifier is conservative by construction and unknown is never safe: a quote-aware splitter (`shell_segments`, so a `|` inside a grep pattern isn't a pipe) breaks the line into pipeline/list segments and bails on anything that can smuggle in another program (`$(…)`, backticks, process substitution, a background `&`, an unbalanced quote); every segment's binary must be in `READ_ONLY_BINS` — no writers, no interpreters (`sh`, `xargs`, `env`, `command`), no installers — with per-command guards for the members a flag can turn destructive (`git` by subcommand, `sed -i`, `awk`'s `system(`/`>`, `tail -f`, and `find`, whose `-exec` argv is judged by the same rules, so `-exec ls` passes and `-exec rm` doesn't); redirects must be incapable of creating a file (`<`, fd dups, `>/dev/null`). File writes (Edit/Write/MultiEdit/NotebookEdit) always ask. The command in the prompt and in the stream's `»` line is never truncated — its tail is where the `| sh` or the second command after a `;` lives.

### Agent mesh

`mesh.rs` (shared) + `src/bin/mux.rs` (CLI, ~all the command logic). Agents in panes coordinate via `mux join/peers/read/post/tell/ctx/brief`, and grow their own tab with `mux split`: the CLI pre-picks the new session name, spools a `SplitRequest` under `requests/`, and the GUI's poll loop applies it (splits must go through the GUI — an out-of-band session would never render and the startup GC would kill it); the CLI learns the outcome by polling tmux for the session (or the spool for a `.err` refusal). `mux new-tab [--cwd <dir>] [--run <cmd>] [--title <t>]` reuses that exact handshake but for a whole new tab rather than a split — a `NewTabRequest` under its own `newtab/` spool (its own `.err` back-channel keyed by session name), applied by `apply_newtab_request` into a fresh single-pane bare `Workspace` that lands in the background (never steals focus, unlike cmd+t); the brief instructs agents to use it only when the user explicitly asks for a tab/window. `mux notify [msg]` raises the caller's tab badge the same way — a fire-and-forget `NotifyRequest` spooled under `notify/` (its own directory: the split drainer eats every json in `requests/`), drained by the GUI's poll tick, stale-cleared at launch. **The tab is the team boundary**: membership is resolved by mapping the caller's `MUXTERM_SESSION` (exported into panes via tmux `-e`) through `state.json` to a stable tab id (`mux-tab-<8hex>`). Isolation is cooperative — enforced at the mux command layer, not by tmux. **Every pane carries a durable single-word codename** (an animal, `workspace::random_pane_name`, unique among live panes) assigned by the GUI at spawn and persisted on the layout leaf in `state.json` (`NodeState::Leaf.name`, serde-`default`) — distinct from the process-scoped `mux join` registry (`agents.json`, pruned on exit). It shows on the pane's HUD bar (`tab_label` falls back to it) and the `mux` CLI reads it (`mesh::pane_names` → `Scope.pane_names`) so `peers`/`brief`/`whoami` name every pane and `resolve_peer`/`tell`/`post` address it; a `mux join <name>` registry name simply wins for display+addressing (checked first), with the codename remaining a valid alias — so a user can say "ask *otter* to do X" and the agent, seeing *otter* in its brief roster, can `mux post otter`. `mux rename` spools a `RenameRequest` (`rename/`) the same fire-and-forget way; `mux retitle` builds on it — it captures a recent slice of every pane in the caller's tab plus the workspace's current title/prompt, one-shots the configured agent's fast model for a `title | description` line (`parse_retitle` takes the *last* non-empty stdout line, so exec-style CLIs' progress noise is ignored), and spools the result; the injected `mux brief` tells agents to keep the name honest with rename/retitle on their own judgement — codename-aware (`rename_guidance`): while the tab still wears its `random_title` codename it leads with an imperative first-action rename ask that names the codename, softening to keep-it-honest once the workspace has a real name (the UserPromptSubmit `--nudge-name` hook reinforces it each prompt until the rename lands). Registry/inboxes/ctx are plain JSON/JSONL files; `mux read` works on any program because panes are real tmux sessions.
